# 每小时巡检与私有备份：可移植 Agent 模板

这是可审阅的配置模板，不是已经运行的服务。实际平台定时器与 Library 操作由用户授权的 Agent 通过支持的连接完成；面板和离线 Python 模块不会自行建立计划或上传。不要将下列占位符原样用作真实身份，也不要将填有用户信息的版本提交到公开仓库。

## 安装时先确认

1. 用户是否明确同意每小时巡检、持续备份和向选定私有 Library 上传。说明巡检活动范围、备份数据类别、目标文件夹、时区/节奏、通知目的地与保留边界；安装或运行本地测试不代表同意持续数据共享。
2. 核验 SOURCE、独立 DATA 和独立 STATE 路径、现有安装身份、有效非空数据库及私有权限。只使用用户选定的 dot 云电脑；不改用本地电脑或另一执行环境。记录可见性，不猜测目录丢失原因或每日重置规则。
3. 在目标服务做一次无副作用读取，确认连接可用并解析精确的私有 Library 文件夹/索引身份。不能按相似名称猜测，不能将凭据或令牌放入提示词。上传需得到该目的地和数据范围的明确授权。
4. 通过实际平台工具读取现有计划并比对目的、范围和执行环境。用户选定的同目的计划优先更新；确认不存在后才按授权创建一个计划。数据库里有计划记录不证明平台上存在或正在运行；不根据恢复出的旧行重建计划。
5. 初次配置/受审迁移由操作者显式批准安装身份与 bootstrap；先完成冻结、扫描、依赖上传和下载核验、全量隔离恢复、索引 CAS 替换与真实回执确认。普通每小时调用永远不带 bootstrap。
6. 检查当前安装模块的 CLI/API 能力和测试结果。`strict-live` 是默认；仅已安装并核验支持时，才在新 run 中选 `--capture-mode database-snapshot-cutoff`。不能改写既有 preparing/prepared run 的模式来消除错误。
7. 保存平台返回的真实计划身份与配置结果，然后分别核验首次实际周期执行。未知状态保持未知；不能以模板、测试或手动试跑代替定时成功证据。缺连接或能力时停在具体阻塞，不虚构后台 cron，不使用 GitHub Actions。

## 私有部署参数

以下由操作者解析并保存在私有配置中，不是公开默认值：

- `[SOURCE_ROOT]`、`[DATA_ROOT]`、`[STATE_ROOT]`：相互独立的已核验根目录
- `[INSTALLATION_ID]`：已确认安装身份，禁止普通运行自动生成
- `[POLICY_FILE]`、`[PREVIOUS_ENVELOPE]`：已审 policy 和最后确认索引的本地持久状态
- `[PRIVATE_LIBRARY_FOLDER_ID]`、`[LATEST_INDEX_LIBRARY_ID]`：明确获准目的地与固定索引身份
- `[PLATFORM_AUTOMATION_ID]`：实际创建/选定后返回的计划身份
- `[TASK_SCOPE]`：获准巡检的活动；不得扫描全部聊天、邮箱或无关项目
- `[TIMEZONE_AND_HOURLY_SCHEDULE]`：用户时间区和每小时安排
- `[NOTIFICATION_DESTINATION]`：已核验的用户私人会话
- `[CAPTURE_MODE]`：已测试安装版本支持的模式；旧安装用默认模式

## 可复制到受支持平台任务的执行提示词

```text
在已授权的同一 dot 云电脑内，每小时对 [TASK_SCOPE] 做只读进展检查，并串行准备 SOURCE=[SOURCE_ROOT]、DATA=[DATA_ROOT] 的私有备份。只向 [PRIVATE_LIBRARY_FOLDER_ID] 上传已授权范围，最后更新既有索引 [LATEST_INDEX_LIBRARY_ID]。真实路径、身份、内容和回执保持私有。

先检查 SOURCE、DATA、数据库、安装身份 [INSTALLATION_ID] 和上次索引。缺失、空库、身份变化、异常缩减、权限/安全问题或未决上传结果都阻止新备份发布。不得创建空 DATA、bootstrap、自动恢复或切换正式 DATA，不得更换电脑。保留最后成功远端索引。

巡检只读取已授权活动并报告有用变化。不要把例行成功心跳写回被备份数据库；它会制造新快照。正式通知状态放在 STATE=[STATE_ROOT] 的专用操作状态中，不进入 SOURCE。遵守既有通知去重和用户渠道偏好。

从当前私有索引读取精确版本，先处理未决 guard/journal 或上传回执；同一尝试使用相同 run 与冻结输入，不盲目重传。仅调用已核验安装模块。使用 [POLICY_FILE] 与 [PREVIOUS_ENVELOPE]；正常执行不传 bootstrap。

捕获模式 [CAPTURE_MODE] 必须匹配已安装能力。默认 strict-live；只有支持且经过测试的安装可显式选择 database-snapshot-cutoff，以冻结 SQLite 中的任务/成果记录选择文件，让后续数据库写入留待下一轮。文件、身份、secret/type、大小/哈希、guard/CAS 和异常缩减检查不能弱化。快照完成时间仅是数据库截止上界，文件另有捕获窗口。

若严格模式因普通并发数据库写入阻塞，同一准备中的 run 最多再试两次，之后报告忙碌并留待下轮；不要无限重试或停止无关工作。只对准备中、未打包且无任何远端行为证据的旧请求，在明确获准的条件下执行窄范围 abandon-preparing；每轮至多一次。不得用它绕过未决上传、秘密、身份、权限或范围问题。

字节未变化则不上传。变化时只打包新内容对象，每包严格小于 19000000 字节；保留全部旧依赖。先验证新私有目录里的完整恢复，再按当前支持的 Library 流程上传，逐项核对结果和下载字节。未知结果先对账，不重复创建；最后以固定索引身份和精确 expected_current_version 执行 CAS 替换，并核实真实回执。

不得删除旧恢复点或依赖，不公开文件，不使用 GitHub Actions，不授予新权限或保存凭据。遇权限、连接或新授权要求时暂停相关动作，报告具体阻塞。

首个失败和原因实质变化时通知 [NOTIFICATION_DESTINATION]，重复相同失败去重；故障后下次完整成功再发送一次恢复通知。区分检查时间、数据库截止上界、最后成功索引确认时间和未经核验的状态。不能承诺云电脑永久保存、每小时必达或自动恢复。
```

计划时间使用 `[TIMEZONE_AND_HOURLY_SCHEDULE]` 在平台的结构化日程中设置；不要只把“每小时”写进提示词就声称计划生效。使用官方返回的观察时间与执行结果更新私有状态展示，界面轮询本地记录不会触发远端备份。

## 验收清单

- [ ] 持续读取/私有上传、目标、范围、节奏和通知获准
- [ ] 已读取并核对同目的既有计划，没有重复建立
- [ ] 初次完整备份依赖齐全，下载字节、SQLite、登记成果与隔离恢复通过
- [ ] 最后索引 CAS 成功，真实回执与固定身份/版本匹配
- [ ] 配置成功与首次实际定时执行分别记录，失败通知可追溯
- [ ] 公开模板无真实 Library/计划身份、私有路径、任务内容或凭据
- [ ] 缺失工作目录、上传未知、版本冲突和并发写入均按失败封闭规则处理

协议细节见[私有备份协议](private-backup-protocol.md)，安装入口见[安装与交接](install.md)。
